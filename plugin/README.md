# NowItKnows

A Claude Code plugin that learns from your work: it uses your skills, learns new ones from your sessions, remembers who you are across projects, and can search your past sessions. It runs on your own Claude plan through the open Claude Code session, with your `claude` CLI available for end-of-session work.

There is also a separately installable native Codex edition. Both packages share learned skills, global memory and session search by default; their hooks, history formats and model calls differ. See [Codex installation](#codex-installation) below. Other Codex profiles keep isolated stores.

## What it does

- **Uses skills.** Every session gets a short skill-use protocol, and each prompt gets a note naming up to three skills that match it. A skill nowitknows learned that runs one repo's own commands or names its files is suggested only in that repo and in repos where you loaded it (`/name` or Claude's Skill tool); `/nowitknows:changes` shows each one's scope. When a skill first shapes the work in a session, Claude starts that reply with a line naming it.
- **Learns.** After enough work in a session, a background reviewer reads what happened and proposes skill and memory updates. Every proposed skill change, and every project note a background review proposes, is checked by an adversarial judge before it is saved; rejected changes are kept with the reasons.
- **Tells you.** Each change appears as one line, for example `NowItKnows · created skill release-ferrylog-cli (judge: pass) file:///...SKILL.md`. Click the link to read the file. Claude is also told each change once, at your next prompt, in fixed words, and mentions it in a sentence of that reply, since apps such as the desktop app keep hook output collapsed; a scripted `claude -p` session leaves them for the next session you work in.
- **Remembers.** USER.md holds who you are and how you want to be worked with (2,750 characters); MEMORY.md holds environment facts and standing conventions (2,500). Both load into every session, one short fact per entry. Procedures belong in skills. Above 85% full, the next background review proposes a tighter rewrite; an adversarial judge must confirm every fact survives before it applies, and the ledger keeps the old text for undo. A rejected tidy waits until that block changes. A missing or empty profile starts with three marked, provisional operating defaults that reviews confirm, revise or remove; existing profiles are never seeded. Project notes live in Claude Code's own memory folder, shared with Codex (see Project notes below).
- **Follows your repos.** A skill learned in a repo knows that repo by its first commit, not its folder, so it is suggested in every clone and worktree of it, on this machine or a new one where your NowItKnows folder was restored. When a clone has no project notes but an earlier copy of the same repo does, you are told once where they are; nothing is moved for you.
- **Searches past sessions.** Requests about earlier work give Claude a small search reminder; `/nowitknows:report` counts hints followed by a search. Archived transcripts outlive Claude Code's 30-day cleanup, up to 1 GiB by default (`NOWITKNOWS_ARCHIVE_MAX_MB`); past that the oldest archived copies are removed.

No skill is deleted: changes are ledgered, skills it made and you stopped using are moved aside, and if the canonical learned-skill library is a git repo every change is a commit (when git can start and commit; otherwise the change stands and `errors.log` says why, with git's own message when git ran). A skill is moved aside only after a month and 20 working sessions in its own repos without use, so time away from a repo doesn't count, or after six months without use while you kept working elsewhere (20 working sessions anywhere); `/nowitknows:keep` brings it back. A crash mid-write can leave an unreadable line in `~/.nowitknows/skills_ledger.jsonl`; until that line is repaired nothing is moved aside automatically, and `errors.log` names the line.

## Install

From the root of a source checkout, set up both detected host CLIs with one command:

```sh
uv run --frozen --python ">=3.14" --project plugin python plugin/bin/nowitknows.py setup
```

This installs or updates each available host plugin and prints a read-only migration plan. Where Codex is installed it adds nowitknows-codex there too; append `--no-codex` to leave Codex as it is. A nowitknows-codex that Codex installed from another marketplace is left as it is. Later, a Claude Code session offers `/nowitknows:setup` at most once every 30 days when Codex appears without nowitknows, and a Codex session with nowitknows offers the two `claude plugin` commands at most once every 30 days when Claude Code is installed without it; neither installs anything itself. Run the same command with `--apply` to merge existing learned data, or use `uv run --frozen --python ">=3.14" --project plugin python plugin/bin/nowitknows.py migrate` to inspect the plan separately. Migration imports durable knowledge only: verified learned skills, global and project memory, and searchable history. It runs one model-free legacy Codex settlement pass before importing, snapshots skill versions and database history, and retains memory overflow. Runtime queues, reservations, staged proposals, rejected changes and old ledgers stay in the legacy Codex store. Before applying, restart Claude Code and Codex so every chat runs the nowitknows you installed (a chat opened before the update keeps its older nowitknows until it is closed), then run the same setup command with `--apply`; the chat asking for it does not hold it up. Apply refuses without writes while a chat on an older nowitknows was active in the last 10 minutes (`MIGRATE_QUIET_MINUTES` in `config.py`), a nowitknows before 0.7 added a memory ledger row in that time, something other than the migration itself wrote the legacy Codex store in that time, or a worker or ledger lock is held; the read-only plan prints the fence's view, naming each old chat. A chat resumed after the restart does not hold it up once the app that ran it on the older nowitknows has quit; Codex records no process, so a Codex chat resumed from an older nowitknows waits out the 10 minutes. Once skills, memory and history are imported, a remaining search re-index runs without the quiet period, even with both apps open. Legacy locks stay held during import as a second line. Interrupted imports can resume. User-authored skills stay untouched. Review and trust NowItKnows's exact Codex hook definitions in `/hooks` after installation; setup prints that step and never bypasses it. `--dry-run` previews setup without installing. Setup refuses a `claude` CLI older than 2.1.301 before any `claude plugin` command. Setup verifies Claude's registered source: the documented GitHub repository, or a local marketplace directory whose `plugin` folder is the one running setup. Run setup from that registered local checkout; foreign or unverifiable sources are refused. A first registration by setup clones the repository without its development files (`--sparse .claude-plugin plugin`).

The shared root is `~/.nowitknows` (or `NOWITKNOWS_DATA_DIR`). Learned skills live in its `skills/` library, linked into `~/.claude/skills` and `~/.codex/skills`. Global memory, history, session search and reports cover both apps; daily token budgets stay separate by host (Claude, Codex and Cursor). A non-default `CODEX_HOME` keeps an isolated store.

The individual host installation paths are also available:

1. **Install uv** once. nowitknows runs on it, and uv fetches the Python it needs.
   - macOS and Linux: `curl -LsSf https://astral.sh/uv/install.sh | sh`
   - Windows: `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`
2. **Install nowitknows** in a terminal:
   ```
   claude plugin marketplace add theaigroup-ai/nowitknows --sparse .claude-plugin plugin
   claude plugin install nowitknows@nowitknows
   ```
   The installed plugin holds only the repository's `plugin` folder, and with `--sparse` the marketplace copy Claude Code keeps in `~/.claude/plugins/marketplaces` holds only that folder and the marketplace file.

   Then start a new session. If nowitknows cannot find or start uv, each session start shows a notice saying so and how to fix it (on Windows the hooks need Git Bash; without it they do not run).

Background learning needs no separate CLI login while a session is open, including in the desktop app. Optionally run `claude auth login` in a terminal: a working CLI login lets end-of-session reviews run right away. Otherwise they wait for later turns in your next Claude Code session, for up to seven days.

Claude Code may report eight options not yet set; their defaults (see Settings) apply until you change them with `/plugin configure nowitknows@nowitknows`. Optionally, run `/nowitknows:setup` for longer transcript retention, git for skills, and tool permissions.

Requirements: Claude Code 2.1.301 or later (background runs and setup refuse an older `claude` CLI, which can lose its login when a short command exits during a login refresh; `claude update` updates it), logged in with your Claude subscription; git, which the setup command above runs to clone the repository (without git it stops with "setup failed; repeat setup to resume"; the plugin itself runs without git, but then learned skill changes are not committed, as described above); uv 0.9.5 or later (older ones cannot install Python 3.14: run `uv self update`, or update uv with the package manager that installed it; a session start says so); and Python 3.14 or later, or uv allowed to download it (its default; with uv's Python downloads off, install one yourself, for example `uv python install 3.14` with downloads set to `manual`). Nothing waits for a download: on a fresh install the session start notice says nowitknows is setting up while uv downloads Python, where none is installed, and nowitknows's packages in the background (about 60 MB), and says again at each session start how that is going, with uv's error if it failed (nowitknows then tries again 10 minutes later). Until that setup has finished, nowitknows's hooks do nothing and its commands say why they cannot run yet. nowitknows's tools wait for it: if it finishes within about 25 seconds of the session's start, as it does on a fast link, the first session gets them; if not, they fail to start, and for about 15 minutes after that Claude Code skips them in new sessions too, so when a notice says nowitknows finished setting up, reconnect nowitknows in `/mcp` (after those 15 minutes a new session starts them as well). If a setup is cut short, by a restart for example, the next session start begins it again. Only that setup runs uv: the session start finds uv on the PATH Claude Code sees, else in `~/.local/bin`, `~/.cargo/bin`, `/opt/homebrew/bin` or `/usr/local/bin`, starting each from the plugin folder, where a pyenv shim may find a Python that has uv. Once nowitknows's environment is built, nothing in nowitknows needs uv. Keep `UV_LOCKED` unset where Claude Code runs (uv 0.11 refuses it together with the `--frozen` flag the setup uses). If uv fails, the hooks never block your prompt or your tools; the session start notice is the only sign.

From a fresh clone instead (Claude Code then runs the clone's `plugin` folder in place, nothing is copied: uv makes its `.venv` there, and edits there apply at the next session start):

```
claude plugin marketplace add /path/to/nowitknows
claude plugin install nowitknows@nowitknows
```

Learned-skill backup is opt-in and private only. After enabling skill-library git history with `setup --git`, setup asks once whether to back up to GitHub, using your installed, logged-in `gh` CLI and a new private `nowitknows-skills` repository; `setup --backup-repo OWNER/NAME` selects an existing verified private repository or a different name. The backup has its own confirmation, including with `--yes`. Without gh or a login, setup prints commands and makes no backup changes. An empty library can be restored from your named repository or the discovered default after confirmation. Background workers fetch and rebase before pushing, check private visibility and scan outgoing history for secrets before each push, and retain both conflicting versions under `.backup-conflicts/` with a notice. Failures leave learning running and notify once per day. The destination and enabled setting live in this machine's data folder (`skill-backup.json`); set `enabled` to `false` there to stop syncing. Status shows the remote, last visibility check and last push result. Opting in sends the library's git history to your private GitHub repository through git and gh; no model or GitHub MCP participates.

## Commands

| Command | Shows |
|---|---|
| `/nowitknows:changes` | recent skill and memory changes with links |
| `/nowitknows:status` | memory owners and usage, the session client or detached CLI login and its extra-usage policy, the past week's sessions by front end, staged changes, background reviews and model runs, with their tokens |
| `/nowitknows:setup` | one-time opt-ins |
| `/nowitknows:keep <skill>` | keeps a skill for good; brings it back if it was archived |
| `/nowitknows:report` | weekly background reviews and tokens, judge outcomes, how often suggested skills were loaded, and per-skill outcomes |

### Optional local viewer

From a source checkout, run `uv run --frozen --python ">=3.14" --project plugin python plugin/bin/nowitknows.py ui` (or `python -m nowitknows ui` from inside `plugin/` with the environment active). The installed Codex entry also accepts `ui`. Append `--open` to open the printed link in your browser; otherwise it only prints the link. Keep the terminal running and press Ctrl-C to stop.

The viewer uses Python's standard library, listens only on `127.0.0.1` on a randomly assigned free port, and requires the random, single-use URL printed at startup. The first successful page request consumes the link. All five views then work inside that page; restart the command for a new snapshot or to reload. Host and Origin checks reject other origins. Hooks never start it.

Overview shows the report's counts as tables. Skills and learning receipts show source identities, content hashes, retained version diffs, sessions, runs, judge verdicts, loads and subsequent review outcomes. Rejections include retained findings; missing evidence is labeled unavailable. Notes shows global memory, project notes stored under the selected data folder, and explicitly labeled historical note backups. Native note and skill folders outside that folder are omitted; current shared notes normally live in Claude's native folder. Source tags are shown when recorded, including `nowitknows-claude`, `nowitknows-codex` and Claude's own notes. Each view has its own share of the page and keeps its newest records; what does not fit is marked and counted as left out for size, never labeled missing.

The page only reads `NOWITKNOWS_DATA_DIR` (default `~/.nowitknows`), creates no data files, and performs no model calls, writes, transcript reads or external requests. Its HTML, CSS and JavaScript are self-contained, with light and dark themes. Stored text is escaped and displayed as text. For a smoke check, set `NOWITKNOWS_DATA_DIR` to a temporary **copy** of a data folder; never test against your live store.

## Settings

Plugin options: `review` (background learning, on), `metrics` (local session counts, on), `reviewer_model` (sonnet), `judge_model` (opus), `os_notify` (desktop notifications, off), `allow_extra_usage` (learn while paid extra usage is on, on; see Plan usage), `share_project_notes` (Claude Code and Codex share one project notes folder per repo, on; the option changes Claude Code only, `/nowitknows:setup --separate-notes` sets both; see What it runs, reads, and writes), `bounded_review_skills` (on: a review that runs inside your session pastes the full text only of skills the session loaded and skills nowitknows may change, and lists your other skills by name and description; off pastes every listed skill while room allows). Environment variables `NOWITKNOWS_<OPTION>` apply when no plugin value is saved; for `allow_extra_usage`, `share_project_notes` and `metrics`, off in either place wins. `NOWITKNOWS_SKILL_SCOPE=0` suggests learned project skills in every repo again (default on). `NOWITKNOWS_JUDGE_NOTES=0` writes background project notes without the judge (default on; `/nowitknows:report` counts judged, accepted and rejected). Background learning normally runs in sessions you work in; scripted `claude -p` and Agent SDK runs are archived and indexed for search but never reviewed, unless you set `NOWITKNOWS_REVIEW_UNATTENDED=1`. `/nowitknows:status` shows whether background learning is on.

## Plan usage

nowitknows runs only on your Claude subscription login (Pro, Max, Team, or Enterprise). It has no setting for an API key, a cloud provider, or a gateway. While a session is open, the hooks module uses that session's client and checks its subscription usage windows before each background model call. No subscription windows means no background model work.

If paid extra usage is on for your Claude account, background runs after you reach your plan's limits can be billed as extra usage, like your own Claude Code use. Set `allow_extra_usage` off (`/plugin configure nowitknows@nowitknows`) to stop in-session calls once any subscription window reaches 100%. A call already running can finish. On Team and Enterprise plans, extra usage can bill the organization.

End-of-session reviews and trigger backfill use the separate CLI path. It strips API and provider settings, refuses a `claude` CLI older than 2.1.301, and checks `claude auth status` before each child. With `allow_extra_usage` off, this path requires Claude Code's cached account details to say extra usage is off; an unknown flag also pauses it, including with a `claude setup-token` login. `/nowitknows:status` reports the session client and its extra-usage policy while the module owns reviews; outside such a session it checks the CLI login and cached flag. If the CLI subscription check refuses an end review from an in-session session, the review waits for the next session without pausing open-session learning. The module does not run trigger backfill, and the start worker skips it for in-session sessions.

Background runs count toward your plan's usage limits like any other Claude Code use. A review that added one skill took about 36 seconds and processed about 23,000 tokens with the default models (sonnet reviewer, opus judge). Reviews run only when a session has piled up enough new work with something in it to learn from (a correction, a fix after an error, a skill in use, a long task), and background learning starts nothing new once a day's runs near 300,000 tokens (a run already going finishes); `NOWITKNOWS_REVIEW_DAILY_TOKENS` changes that (0 for no limit). The ceiling protects ordinary work from repeated learning calls; 300,000 is a provisional default, not a measured optimum. It counts background model work only, resets at local midnight, and does not stop routing, memory or search. `/nowitknows:status` shows the session client or detached CLI login and the last week's reviews, model runs, and tokens by model.

## Results

These controlled comparisons ran the same model and tasks with and without NowItKnows: 3 task families, 2 repeats, 48 sessions, with the host's own memory on. Counts include foreground and background tokens, including cached input; they do not measure subscription credits or cost.

- Claude Code, four runs on 0.11.2 through 0.11.5: 24/24 tasks passed vs 8/24 on average, with 12% fewer total tokens on average.
- Codex, three runs on 0.11.2 and 0.11.4: 24/24 tasks passed vs 6/24 on average, with 7% fewer total tokens on average.
- Hermes Agent comparison, 0.9.0 (under the earlier name learnloop): 24/24 vs 7/24 tasks passed, at 0.69 times Hermes's total tokens, reconciled against the provider console.

The tasks teach a procedure and its pitfall once, then repeat that kind of task, which is the case this tool is built for. The score without it varies between runs: Claude Code passed 7 of 24 in the 0.9.0 and 0.11.2 runs and 12 of 24 in the 0.11.1 run, on the same CLI and tasks.

With no teaching, where every session gets only the goal and the rules are readable in the repository, the final run passed Claude Code 22/24 vs 19/24 tasks and Codex 20/24 vs 16/24. Averaged with the run before it, total tokens were 20% more on Claude Code and about even on Codex. In the final run it saved a correct skill in 3 of 6 and 5 of 6 task sequences, later sessions loaded it every time, and no wrong procedure was saved. Treat those task counts as about even: Claude Code's gain came in a family where nothing was saved, and Codex's in a family plain Codex passed none of in that run, with an earlier run at 16/24 vs 17/24. Savings come from fewer failed attempts: on tasks the agent already handles, NowItKnows can cost more than it saves.

Codex exec runs with a recorded successful file change inside git may learn skills and project notes at session end, using up to half of Codex's daily review allowance; no-edit runs remain search-only.

## Limits

- SKILL.md and each support file have a 30,000-character limit, never a target. Reviewers put detail needed only sometimes in references/ through ordinary reviewed changes. Nik never automatically splits or shortens skill text. Writes over 30,000 stay whole with a returned and logged warning; existing oversized skills get no cleanup pass. The existing SKILL.md ceiling of 100,000 characters still refuses larger changes before saving, so those changes do not apply. Support files have no separate byte ceiling.
- Nik does not police CLI accounts: in-session reviews use that session's client; session-end reviews and trigger generation use the CLI's login, whichever account it is.
- Claude Code on macOS, Linux and Windows, and Codex on macOS and Windows. Real use and the benchmarks are on macOS. Linux has automated test runs only, and Codex on Linux has only offline tests with a stand-in CLI. On Windows, install, hook and tool probes pass on GitHub's Windows runners; real sessions, a background job outliving the app, and console window flashes still need confirmation on a real machine. Cursor on Windows is not yet supported. A Cursor edition is included but not yet proven: when taught, it passed 8/8 vs 5/8 tasks with 52% fewer tokens on 2 task families. With no teaching, two runs saved a skill in 2 of 3 and 1 of 3 task families, at 17% and 32% more total tokens, and the latest passed 12/12 vs 12/12 tasks. Claude Code supports the terminal, IDE extensions and desktop Code tab; claude.ai chat and Cowork refuse the plugin.
- Background learning needs your own subscription login: Claude Pro, Max or Team (also Enterprise), or a ChatGPT plan for Codex, never an API key. With paid extra usage on, runs past your plan's limits can be billed as extra usage; `allow_extra_usage` off skips in-session calls at a reached limit and pauses CLI calls while extra usage is on or unknown. With an API key, Bedrock, Vertex, or a gateway, the skill protocol, router, session search, and memory tools still work, but nothing learns in the background.
- Learning spends plan tokens on background reviews: a review that changes a skill processes about 23,000 tokens (Sonnet reviewer, Opus judge).
- It is gradual: the first review comes after about 10 prompts or tool rounds, or at the end of a session, and a skill pays off when the same kind of task comes back.
- New notes cannot use Windows device names such as `aux`, `con` or `com1` on any OS, including macOS and Linux, because notes are shared across machines. Existing notes remain readable and editable.
- Session search is keyword-based, with no semantic search.
- The reviewer prompt was adapted from Hermes Agent (MIT); see [Third-party notices](THIRD_PARTY_NOTICES.md).
- The router matches words, not meaning (no embeddings, by design): on our 174-prompt test set it puts the right skill in the top 3 for 79% of prompts and suggests a wrong one for 4%.
- The judge cuts bad skill changes, not to zero; every change is ledgered and reversible.
- It relies on Claude Code and Codex internals that can change, including hook inputs, transcript formats and tool result wording; host updates can break parts of it.
- Routing adds a short delay to each prompt. On one Mac with 1,000 skills, the complete hook measured about 97 ms Claude and 102 ms Codex at warm p50. Since 0.9.0 the Claude hooks start nowitknows's own Python directly, with no uv on the way. On a 2-CPU Windows runner, prompt p50 was about 300 to 460 ms against 5 s hook limits. These are local measurements, not latency guarantees.
- Open-session learning uses the session's login. If the separate CLI login is missing or expires, end-of-session reviews wait for the next session, for up to seven days. A desktop end-to-end run of this module path has not yet been verified.
- Token savings depend on repeated work and are not universal: in the taught runs above, codegen used 34% fewer tokens on average, while release and tests used 9% more, passing more tasks.
- After an update, restart the app: a running session keeps the tool server it started with, and Codex asks you to review and trust the hooks again.
- Built for one person. Nothing syncs between computers or people unless you turn on the optional GitHub backup of your skills.
- Claude Code Projects (not yet tested with nowitknows): a "Work locally" thread runs on your machine and should get everything above, though routing and memory reviews there depend on how the project conversation hands it your messages. A cloud thread runs on a temporary VM and gets plugins only from Project settings > Plugins, which may refuse nowitknows (claude.ai refuses plugins with a top-level `bin/` folder elsewhere); if it loads, nowitknows gives the skill protocol and router only and saves no skill or memory changes, because nothing on the VM lasts. To use a learned skill in cloud threads, copy it into the repo's `.claude/skills/` and commit it.

## What it runs, reads, and writes

- **Runs:** its hooks, commands, hooks module's calls and MCP server through `bin/nowitknows.sh` (a sh script, which the MCP server and hooks module reach through `bin/nowitknows`, on Windows `bin/nowitknows.cmd`; the hooks run through `/bin/sh`, or on Windows through Git Bash), which runs the plugin environment's own Python once the background setup has marked that environment ready, and until then nothing but, at a session start, `uv --version` and `uv python find` (with the uv on your PATH, else `~/.local/bin/uv`, `~/.cargo/bin/uv`, `/opt/homebrew/bin/uv` or `/usr/local/bin/uv`) and that setup; the setup, `bin/bootstrap.sh`, runs `uv sync` for the plugin's environment in the background on a fresh install or after an update in place, started through `setsid` or, on macOS, `/usr/bin/perl` so that it outlives the hook, checks whether it still runs with `ps` (or `/proc` on Linux), and moves aside a half-made `.venv` in the plugin folder; a TypeScript hooks module that calls Python through that script and runs background reviewer, judge, and reviser calls on the session's client after a turn; a detached background worker that archives and indexes sessions and uses your own `claude` CLI in headless mode (`claude -p`, after `claude --version` and `claude auth status`) for end reviews and trigger backfill; to find the running `claude` when it is not on your PATH, a read of `/proc/<pid>/exe` on Linux or `ps` on macOS; `git add` and `git commit` in your skills folder after each skill change when that folder is a git repo, plus `git status` when one of them fails (a git that cannot start, or that fails, for example with no user.email or a failing hook, leaves a line in `errors.log`, with git's message when it ran); and `git init` there only if you choose it in `/nowitknows:setup`; and, where Python has no zstd module (before 3.14), the `zstd` command, if installed, to read Codex's compressed chat history, its output read through a pipe, never written to a file.
- **Reads:** Claude Code's session transcripts (`~/.claude/projects`), the `.git` entries of the session's folder and its parents (to name the repo the way Claude Code does, without running git), the skills Claude Code can see (yours, the project's, and installed plugins'), the CLAUDE.md and rules files a session loads, the project notes in Claude Code's memory folder for the session's repo (Claude Code's own included, to inject and route them while Claude's memory is off, in Codex, and in background reviews), Claude Code's settings files (user, project, local, managed), the environment variables that name the session's front end (entrypoint, attended, remote, remote environment type, environment kind, and session kind, plus whether a claude.ai project id, the Projects-session flag, a Remote Control id, or hosted memory is set, recorded as yes or no; kept per session in `~/.nowitknows/state.json`), the open session's subscription usage windows, and Claude Code's account config (`~/.claude.json`, or `~/.claude/.config.json` when that exists), only to check that detached runs would use your subscription and whether extra usage is on. With Codex set up (its package, `nowitknows index`, or the migration): Codex's chat history in your Codex profile (`sessions` and `archived_sessions`, plain, gzipped or zstd-compressed `.jsonl.zst`) and its chat-import records (`external_agent_session_imports.json`, `claude-cowork-import-history.json`).
- **Writes:** `~/.nowitknows` (memory, ledgers, staged and rejected changes, background model steps and replies, durable detached replies and usage receipts, queued end reviews, a search index of your sessions, including the commands Claude ran with secret-looking values replaced by [redacted], gzipped transcript copies, a local activity log of router suggestions, recall hints, skill loads with the repo each ran in, learned project skills left out of a prompt, and session searches for `/nowitknows:report` and the scope of learned skills, that scope itself (`skill_scope.json`), the background setup's record, output and note that it finished, `bootstrap.pid`, `bootstrap.log` and `bootstrap.finished`, and, while nowitknows's tools wait for that setup, `mcp-wait.<Claude Code's process id>`), its Python environment in the plugin folder (`.venv`, which uv makes, holding the setup's `nowitknows-ready` mark, and `.venv.incomplete`, where the setup moves one an interrupted install left half made), learned skills in `~/.nowitknows/skills` with links in both hosts' skill folders, the project notes nowitknows saves in Codex, and in Claude Code while Claude's memory is off (one Markdown file per note, each tagged with the app that wrote it, plus their lines in `MEMORY.md`), in Claude Code's own memory folder for each repo (`~/.claude/projects/<repo>/memory`, or the folder your user or managed settings choose, or your local settings in a repo you have told Claude Code to trust; a repo's checked-in setting is ignored; created on the first note even before Claude Code has run there; nowitknows changes only the notes it wrote there and keeps its lock, ledger and backups of every note version in `~/.nowitknows`), and, with note sharing off (`/nowitknows:setup --separate-notes`), when you turn Claude Code's auto-memory on or off, copies of your project memory files into the folder that takes over, plus a `.nowitknows-migrated-<time>` marker file in the folder that gave them up (which can be Claude Code's auto-memory folder; the lock for the move stays in `~/.nowitknows`). `/nowitknows:setup` changes `~/.claude/settings.json` only for the opt-ins you confirm (keeping notes separate adds `NOWITKNOWS_SHARE_PROJECT_NOTES=0` to its `env` and `share_project_notes: false` to `~/.nowitknows/codex-settings.json`); applying the migration copies the notes nowitknows kept in `~/.nowitknows/projects` into those folders, leaving the originals in place beside a `.nowitknows-migrated-...` marker. With `os_notify` on, change notices also go to your terminal as desktop notifications. On Windows, `~` is your user profile folder (`%USERPROFILE%`), the one Claude Code uses, even where Git Bash sets another HOME; only the sh scripts in `bin/`, which run under Git Bash, use the shell's HOME, for the uv installs they look for and, unless `NOWITKNOWS_DATA_DIR` is set, the setup's files in `~/.nowitknows`.
- **Fetches:** on a fresh install, the background `uv sync` that the session start begins downloads, if no Python 3.14 or later is installed, a Python build through uv (about 27 MB, once per uv Python folder, so again on every fresh machine, container or cloud session), and the `mcp` Python package and its dependencies (about 30 packages, every version pinned in `uv.lock`). The optional GitHub backup talks to GitHub through git and `gh`. Cursor setup installs the pinned official SDK through npm, and the managed Codex installer prepares its runtime through uv. Background reviews go through your own Claude Code, Codex or Cursor login. Nothing else goes over the network except those apps' own requests, including their plugin installs.

nowitknows sends no telemetry off the machine: `activity.jsonl` is a local log of router suggestions, learned project skills left out because the prompt came from another repo, recall hints, skill loads, and session searches read by `/nowitknows:report` and the optional local viewer. `session_metrics.jsonl` adds local session counts: tokens, active time, turns, calls, failures and correction signals, with host/session/repository identifiers and skill names/counts. `session_metrics_state.json` keeps one small record per source file: path, size, mtime, scan time and per-session counts, plus collection progress. Changed files are read whole; deleted or shortened sources stop contributing their old counts. There is no metrics database, transcript offset, stored message id or prompt mirror. Metrics retain no prompts, commands, referenced file names, tool output or skill bodies. Auxiliary usage/activity continuity receipts are `session_metrics_coverage.json` and `session_metrics_activity_coverage.json`. Collection runs in a detached low-priority process after end/stop review locks are released and finds new subagents and unended sessions too. `metrics --backfill` scans all changed files now with progress. The report compares per-session totals including subagents within the same repository and origin, refuses comparisons of very different session lengths, and reports missing foreground shares as unknown. Turn collection off with `NOWITKNOWS_METRICS=0`, the Claude `metrics=false` option, or native `configure metrics=off`. To clear it, turn it off, let any active collector exit, and remove `session_metrics*` files from the configured data folder, including any old unreleased SQLite files. While collection is on, history is rebuilt. The report names its files and states collection status. These observations are evidence, not proof of savings. Background reviews go through the open session's Claude Code client or your `claude` CLI to Anthropic like any Claude Code request, carrying excerpts of the session being reviewed. With shared project notes a review also carries the notes in the repo's memory folder, so a Codex review sends Claude Code's own notes to OpenAI and a Claude Code review sends the notes Codex saved to Anthropic; the judge of a proposed note reads the other notes' names and descriptions. Turn sharing off to keep each app's notes with its own vendor. See [Third-party notices](THIRD_PARTY_NOTICES.md) for Hermes Agent attribution. To report a vulnerability, see `SECURITY.md`.

Project notes are shared between Claude Code and Codex, in Claude's memory folder for each repo: notes Codex saves through nowitknows are there for Claude Code, which loads them like its own while its memory is on, and Claude's own notes are there for Codex. Sharing changes where notes live, not who writes them: with Claude's memory on, Claude writes its notes itself and nowitknows only checks them; nowitknows's `memory` tool and background reviews write project notes in Codex, and in Claude Code while Claude's memory is off. A project note a background review proposes is checked by the judge before it is written, like a skill; if the judge drops it, the note is not saved, `/nowitknows:status` counts it, and the reason is in `~/.nowitknows/rejected`. Your own `memory` tool calls in a session are written at once.

nowitknows changes only the notes it wrote, as it wrote them, and, in `MEMORY.md`, the exact line it last wrote for each (Claude Code's own notes, a nowitknows note Claude has edited, which nowitknows's later updates leave for a new name, and any line Claude wrote or changed, even a nowitknows line with Claude's text added, stay as they are). It adds index lines only up to 180 of `MEMORY.md`'s 200 and its bytes only up to 22,500 of 25,000, leaving room for Claude; when its share is full, the tool asks to remove or shorten stale notes in the same call, and a background review that could not save a note says so in a notice (once a day for each folder) and in `/nowitknows:status`. Files it writes in Claude's folder keep the permissions of the files they replace. When a prompt calls for a note, Codex (and Claude Code with its memory off) gets nowitknows's own notes whole and a one-line pointer to any other, which it can open itself; index lines that look like secrets or instructions are left out.

In Codex, a command that names a notes folder must only read: a direct write (`apply_patch` or a shell command), deleting, moving or copying over a folder that holds notes (including a shell fed a script on its input, and a python, node, ruby or perl call that deletes or moves such a folder), and also copying notes out or reading them through a script, is refused with a pointer to the memory tool; `cat`, `head`, `grep` and the other plain reads, also piped or in a loop, still work. This is a speed bump for the model's own calls, not a sandbox: it does not cover another MCP server's file-write tools, code in a tool field other than `cmd` or `command`, or input typed into a running process, and on Claude Code it reads only Write, Edit and MultiEdit (a Bash `sed -i` or redirect into the folder is not read). A call too large for the full check is judged by the notes paths it spells out. `/nowitknows:changes` lists every note change with links and backups, and `/nowitknows:status` shows the notes home.

To keep notes separate for each app, choose `--separate-notes` in `/nowitknows:setup` (or set `NOWITKNOWS_SHARE_PROJECT_NOTES=0`); the change reaches the background reviews (also ones already queued) and memory writes of sessions already running, setup prints how to share again, and isolated Codex profiles always keep their own. The plugin option changes Claude Code only; Codex has its own `configure share_project_notes=off`.

Notes nowitknows kept before 0.8.0, in `~/.nowitknows/projects`, are not seen by sessions until they are migrated; nowitknows says so once for each repo and app at session start, and `/nowitknows:status` counts them. The setup command previews the migration by repo, with the folder each repo's notes go to and the setting that chose it, without changing anything; with `--apply` it copies them once no chat on an older nowitknows has been active for ten minutes, keeping originals, never overwriting a note Claude wrote (a different note under the same name arrives under a suffixed name), and keeping anything past the limits outside the folder with a notice. In Codex the setup skill runs `migrate` and `migrate --apply` for you.

## Codex installation

The native Codex 0.11.6 edition is a local package for macOS and Windows; on Linux it has only offline tests. It runs on your own ChatGPT-authenticated Codex CLI, shares the learning engine above, and shares learned data with Claude's default profile.

### Codex-first install from the catalog

On macOS/Linux, with Codex and uv already installed, you can add nowitknows straight from the repo's catalog. On Windows, use the managed installer below from a source checkout; it generates Windows commands automatically:

```sh
codex plugin marketplace add theaigroup-ai/nowitknows
codex plugin add nowitknows-codex@nowitknows
```

The marketplace must keep its name, `nowitknows`: nowitknows's MCP server is found at `<CODEX_HOME or ~/.codex>/plugins/cache/nowitknows/nowitknows-codex/<version>/`, and under another name its tools do not start (Codex's log then names the path it missed). Open a new Codex session and trust nowitknows's eight hooks in `/hooks`. The first session starts a background setup that builds nowitknows's Python environment under `<profile>/nowitknows-runtime/` and says so; if it finishes within about 25 seconds the tools start in that session, otherwise in the next new one, and a later prompt says when the setup finished. A session that started before the setup was ready gets nowitknows's start (protocol, memory, notices) at its first prompt. If Claude Code is installed without nowitknows, Codex mentions, at most once every 30 days, the two `claude plugin` commands that add it there.

The managed installer below is the other route: it binds a retained runtime and profile at install time.

Prerequisites: macOS/Linux, or Windows with Git Bash and user-level uv; an existing native Codex CLI with `plugin marketplace ... --json` and `plugin add ... --json` support (tested with 0.162.0-alpha.17.2), and standalone uv. The command below lets uv select a supported Python, so the system Python can be older than 3.14. The installer finds `--codex-bin`, then `NOWITKNOWS_CODEX_BIN`, then a saved target/active release executable, then `codex` on PATH, then the CLI already bundled in `/Applications/ChatGPT.app` or `~/Applications/ChatGPT.app`. It finds uv on PATH or in the standard standalone install locations. It prints the selected binaries, profile and workspace before installation. It never downloads, installs or upgrades a global CLI. uv prepares Python dependencies from the shipped `uv.lock` using `--frozen --no-dev`; a first install can require network access for Python/packages. Model work uses the selected profile's own ChatGPT login. No credentials are copied.

From your project folder, run the installer from where its files are. In a source checkout they are in its `plugin` folder; replace `/path/to/nowitknows-plugin` with the checkout's location:

```sh
uv run --frozen --python ">=3.14" --project "/path/to/nowitknows-plugin/plugin" python "/path/to/nowitknows-plugin/plugin/tools/install_codex.py"
```

A repository source archive uses the checkout layout above. If you have a portable Codex release archive, extract it first. Its installer is at the top of the `nowitknows-codex-VERSION` folder; replace `/path/to/nowitknows-codex-VERSION` with that folder:

```sh
uv run --frozen --python ">=3.14" --project "/path/to/nowitknows-codex-VERSION" python "/path/to/nowitknows-codex-VERSION/tools/install_codex.py"
```

The default profile is `CODEX_HOME` when set, otherwise your normal `~/.codex`. To select a different profile explicitly, append `--codex-home /absolute/path/to/profile`. The installer keeps your current working folder. Append `--dry-run` to inspect paths and planned operations with no writes or CLI calls. The catalog install above uses the source manifest as it is.

The installer selects immutable bundle/runtime locations under `<profile>/nowitknows-installer/releases/<version>-<source-hash>/`, prepares the pinned runtime before registering the local marketplace, and installs `nowitknows-codex@nowitknows-codex-local` through Codex's normal native installer. Its output includes exact launch, doctor and hook-definition paths. Run the same command again to resume a partial installation or confirm `already-installed`. The generated entry point retains the selected executable as its default for hooks, MCP, controls and doctor, even without that CLI on PATH. A nonempty `NOWITKNOWS_CODEX_BIN` override wins. A release version cannot silently acquire different source bytes or a different saved executable: either change requires a new native manifest version. `--out /absolute/path` is optional; an existing release keeps its original bundle location.

Use the printed launch command to open Codex with the same profile and workspace. Open `/hooks`, inspect the eight definitions from **nowitknows-codex**, including each command's preserved runtime path, and trust those exact definitions individually. The events are SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, SessionEnd, PreCompact and PostCompact. Leave other hooks as they are. Installation does not mark hooks trusted; Codex skips definitions pending review. Repeat the review when Codex requests it after an update. Restart Codex or the desktop app and open a fresh chat to load the installed release. See the [native hook review instructions](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks).

To update, use a checkout of the next release, or extract its portable Codex archive if available, and run the corresponding installer command. It deliberately removes and adds only its own previously managed marketplace source. A source it has not managed causes a stop. To migrate an older local installation, rerun with `--replace-source /exact/old/marketplace/root`, using the exact path the error reports. This opt-in only adopts that local NowItKnows source. It never adopts a Git source or another marketplace.

Codex's native installer prunes old version caches. Before invoking it, this helper snapshots all existing NowItKnows version caches, including 0.5.0 and 0.5.1, then restores missing directories and files at their original paths even after a failed install. New release hooks, MCP and command skills use the preserved runtime outside that cache, so future upgrades keep those runtime paths available. Legacy chats should be idle during the first migration: native cleanup creates a short interval before the old cache paths can be restored. If installation is forcibly killed during that interval, rerun it to restore the durable cache snapshots. Snapshots and runtime versions are retained, so allow disk space for older environments.

Recovery uses the same profile-selection rules and works from any surviving source release, without checking out an older source tree. From a source checkout:

```sh
uv run --frozen --python ">=3.14" --project /path/to/nowitknows-plugin/plugin python /path/to/nowitknows-plugin/plugin/tools/install_codex.py --rollback 0.5.2
uv run --frozen --python ">=3.14" --project /path/to/nowitknows-plugin/plugin python /path/to/nowitknows-plugin/plugin/tools/install_codex.py --remove
```

From an extracted portable Codex archive, if available:

```sh
uv run --frozen --python ">=3.14" --project /path/to/nowitknows-codex-VERSION python /path/to/nowitknows-codex-VERSION/tools/install_codex.py --rollback 0.5.2
uv run --frozen --python ">=3.14" --project /path/to/nowitknows-codex-VERSION python /path/to/nowitknows-codex-VERSION/tools/install_codex.py --remove
```

`--rollback VERSION` selects a release previously installed by this helper. Older pre-helper caches are retained for active chats but are not automatically converted into rollback releases. `--remove` uses native plugin and marketplace removal, then restores retained caches for existing chats. It leaves all release runtimes, cache snapshots, the installer ledger, memory and learned skills in place. Restart the host to finish deactivation. Do not manually delete the installer folder or retained caches while chats still use them. A failed registration/activation can leave the marketplace on the new source while the prior release remains recorded as active; retry or explicitly roll back. The individual Codex installer does not migrate data; use the shared setup/migrate command above.

Ask for the native `nowitknows-codex:nowitknows-setup` skill to inspect setup and change preferences. Status, doctor, changes, keep and report have the same prefix. Global memory and canonical learned skills default to `~/.nowitknows/memory` and `~/.nowitknows/skills`, with links under `~/.codex/skills`; project notes go to Claude Code's memory folder for each repo (`configure share_project_notes=off` keeps them in nowitknows's own store); Codex's native memory is left alone. Older local chats are indexed for search without running reviews on their past work.

Codex supplies a matching skill or project-memory body once per context, then uses a short pointer. Edits, compaction and resume cause a fresh delivery. A learned project skill is supplied only in its repos, as in Claude Code; reading it with `skill_view` in another repo adds that repo, an automatic delivery does not, and `configure skill_scope=off` supplies it everywhere. The report separates automatic deliveries, pointers and observed explicit `skill_view` reads; none proves the model followed the instructions. Discovery uses the profile's saved settings and workspace files. Temporary launch overrides do not automatically reach the separate catalog process; use saved native skill settings for normal operation.

Reviews use separate native CLI sessions, with the same reviewer/judge settlement and daily token budget as the Claude edition. As there, a review pastes the full text only of skills the chat loaded or read and skills nowitknows may change; `configure bounded_review_skills=off` pastes every listed skill while room allows. Extra account usage is allowed by default, matching Claude's current setting. Routing, memory and search keep working. No model API keys, provider SDKs, credit purchases or resets are used.

Windows install and launch pass automated runs on GitHub's Windows runners, which also ran the hook commands directly and started Codex's app server with hooks off and no login. Hooks firing inside a real Codex session and logged-in learning on a real Windows machine remain unverified. Windows uses the source-checkout managed installer, not the raw repo catalog or a Mac-built portable archive. Review and trust hooks through Codex normally. ## Cursor background learning

Every Cursor background job uses the latest Grok through the official Cursor SDK on your own login. The account's listed highest Grok version is cached for 24 hours, retaining valid cached IDs and their timestamp if listing fails; `grok-4.7` is an unwritten fallback only when no valid cache exists. Reviewer, reviser, triggers and tidy use medium reasoning; judge and note judge use low. All use context 256k and fast=true. Your foreground Cursor model remains your choice. Cursor account spending settings decide whether calls can bill past the plan; `allow_extra_usage=off` cannot enforce included usage on Cursor.

If Grok is unavailable, the plan refuses it or the SDK is missing, learning pauses. Status and doctor give a plain fix: run `/nowitknows-setup` for SDK login and check Grok plan availability. Skills, memory and search keep working. Old model selectors, routing choices, SDK opt-ins and parameter overrides are ignored safely; their saved files and all user data remain in place.

Setup requires Node 22.13 or later and npm, installs the pinned official SDK in a staged runtime, and retains the user's SDK login as the consent step. Never paste keys. SDK runs follow your account's Privacy Mode, use an empty temporary workspace without tools, MCP or settings sources, and refuse tool events, Max Mode and invalid replies. Spending guards and sanitized failed-call receipts remain in force; rejected or unjudged skill changes and project notes are never applied.
