# Security

## Reporting a vulnerability

Report vulnerabilities privately through GitHub's private vulnerability reporting: on https://github.com/theaigroup-ai/nowitknows, open the **Security** tab and choose **Report a vulnerability**. Please do not open a public issue for a security problem.

Include what you found, how to reproduce it, the nowitknows version (`version` in `.claude-plugin/plugin.json`), and the Claude Code version (`claude --version`).

## Supported versions

Security fixes go into the latest release.

## Scope

In scope, among others:

- A background run (`claude -p`) that starts without a Claude subscription login, with an API key, cloud provider, or gateway in effect, or with paid extra usage on while `allow_extra_usage` is off (`nowitknows/claude.py`).
- Credentials nowitknows handles leaking: environment credentials (API keys, tokens) other than the stored login or setup-token reaching a background child's environment, or the login, the setup-token, or such environment credentials reaching a prompt file, a log, or the search index; session ids reaching a child's environment.
- A skill or memory path that escapes its folder (path traversal, symlinks), or writes beyond those listed under "Writes" in the README.
- Archiving a skill nowitknows does not own (one you wrote, asked for, or kept), or any write to synced, plugin, or project skills.
- Content that bypasses the safety scan into memory or a skill (prompt-injection phrases, secret shapes, hidden characters), or a background skill change that applies without passing the judge.
- Deleting user data instead of archiving or ledgering it.

Out of scope: vulnerabilities in Claude Code itself (report those to Anthropic); residual risks from settings from the Windows registry, MDM profiles, or server-delivered managed settings; TLS-intercepting proxies; extra usage on a setup-token login; Claude Code's cached extra usage flag being up to about a day old; text you typed or pasted into a session, secrets included, reaching the local search index, review digests, or the debug log (nowitknows keeps session text on your machine, as Claude Code's transcripts do); and what a model writes into a skill the judge passed, unless it carries secrets or injection the scan should have refused.


## Native Codex installation and recovery

The installer uses the user's existing native CLI and selected Codex profile. It discovers an explicit CLI, the configured `NOWITKNOWS_CODEX_BIN`, PATH, or the existing ChatGPT.app bundle; it never downloads or updates a CLI. A standalone uv prepares dependencies from the shipped lockfile. The CLI owns authentication. NowItKnows does not read or copy credentials, change hook trust, bypass review, or alter another plugin's configuration. The normal native installer can change this plugin's registration and enablement.

The installer owns `<CODEX_HOME>/nowitknows-installer`, its generated local marketplace, and only `nowitknows-codex@nowitknows-codex-local`. A new release is bound to its source hashes, profile and immutable runtime path; a different source under an existing version is refused. An unmanaged marketplace requires the explicit exact `--replace-source` path. Unexpected native JSON, path mismatches and changed bundle/cache bytes stop installation. No model calls are part of installation. Local ledgers and checksums are recovery evidence, not an authenticity boundary against someone who can edit the user's files.

Native cache pruning is compensated by durable snapshots and restoration at the original paths. A killed installer may need a rerun to restore those paths; legacy chats should be idle during migration. Managed runtime paths are outside the native cache and remain available across updates. Rollback and removal retain all snapshots and releases. The default shared memory store (`~/.nowitknows`), the retained legacy Codex store (`~/.nowitknows/codex`), the isolated `<profile>/nowitknows` store for a nonstandard profile, writable skills, explicit data/skill overrides, and Claude's installation are not erased. Do not remove retained runtime folders while active chats still reference them.

Report an unexpected marketplace replacement, loss of retained caches or data, a profile/cwd binding error, a hook-trust write, credential access, or modification of another plugin as a security issue. Include the native plugin version from the generated `.codex-plugin/plugin.json`, the build receipt, and `codex --version`, with private paths/content redacted.

## Shared project notes

Version 0.8.0 writes project notes from both Claude Code and default-profile Codex into Claude Code's own memory folder for each repo, the folder Claude Code's own rules select (`CLAUDE_COWORK_MEMORY_PATH_OVERRIDE`, else `autoMemoryDirectory` from the managed settings, the repo's local settings (only in a repo Claude Code has been told to trust) or the user settings, else `<CLAUDE_CONFIG_DIR or ~/.claude>/projects/<repo>/memory`), creating it as a real folder on the first note even before Claude Code has run there. Notes folders that are links, and linked note or index files, are refused, since a link breaks Claude Code's own memory writes. A repo's checked-in `.claude/settings.json` is never used for that folder (Claude Code's schema says it ignores the value), so a cloned repo cannot aim nowitknows's notes elsewhere, and a value Claude Code would drop (relative, `/`, a network share, `~` reaching the home folder or above it) leaves the default folder; nowitknows also refuses the home folder itself and its own data folder. Isolated Codex profiles, the opt-out (`/nowitknows:setup --separate-notes`, which also reaches reviews queued before it) and hosted project memory keep their own stores. Codex's internal memory database (`~/.codex/memories_1.sqlite`) is never read or written.

nowitknows writes notes only through its memory tool and background reviews, and only where it owns project memory (Codex, and Claude Code with Claude's memory off; with Claude's memory on, Claude writes its own notes and nowitknows only checks them), with the existing secret and injection refusals and Claude Code's size limits. A note a background review proposes is judged by an adversarial model before it is written, with the same fail-closed verdict handling as a skill change (a rejected note is dropped and recorded, a judge that cannot answer leaves it queued); the judge sees the proposed note, the other notes' names and descriptions, and an excerpt of the session, and these go to the review's vendor (Anthropic for Claude Code, OpenAI for Codex), so with sharing on a Codex review reads Claude Code's own notes and a Claude Code review reads the ones Codex saved. A file it writes in Claude's folder keeps the mode of the file it replaces; its own files stay private. In a shared folder it changes only notes it wrote (tagged `metadata.source: nowitknows-claude` or `nowitknows-codex`) and only while a note is exactly the version it last wrote (by the fingerprint its ledger records; Claude Code keeps the tag when it edits a note, and a changed note is Claude's from then on, never changed or removed, a later update going to a new name), and, in `MEMORY.md`, only the exact line it last wrote for each of them, which its ledger records: Claude Code's own notes and index lines, including a line that shares a nowitknows note's link with other content and a nowitknows line that anyone has changed or added text to, are never overwritten, removed, reordered or dropped. Every index edit reads `MEMORY.md` again and replaces it atomically only if it is unchanged since that read, retrying a bounded number of times and then failing closed; a small window remains between the last check and the rename, since Claude Code takes no nowitknows lock. An interrupted write or migration import is finished only into the folder it recorded (no link, the same real path, device and inode); otherwise it stays open and writes nothing, and every import into that folder waits until it is back. Any unfinished import needs the migration's quiet fence. nowitknows adds index lines only up to 180 of 200 and grows `MEMORY.md` only up to 22,500 of its 25,000 bytes; a note a background review could not save there is recorded and announced. Into a session it routes the bodies only of its own notes as it last wrote them; any other note goes out as a one-line pointer (path, size and redacted description), never its body, and an index line that looks like a secret or an instruction is left out of the injected index. Every note version is ledgered with a backup in `~/.nowitknows/memory-history`; removal archives the note first. A notes folder inside Claude's or Codex's config folder other than a project's `memory` folder is refused, since a note in `agents`, `commands` or `skills` would run; Claude Code's gate also covers a checked-in `autoMemoryDirectory`, which Claude Code 2.1.296 may write to in a trusted repo.

Trusted Codex PreToolUse hooks refuse `apply_patch` paths, Claude-style edit tools and shell commands (also another MCP server's command) that touch a notes folder (any spelling: absolute, `~`, variables including ones the command sets itself, loop variables, `$(pwd)` and `${VAR:-default}` forms, relative, workdir, `cd`, `pushd` and `popd` sequences followed in order through subshells, scripts given to a shell with `-c` or on its input by a here-document or here-string (a shell with no -c and no script file, -s allowed) and their arguments, also in an argv list, a patch by its Add File, Update File, Delete File and Move to lines in whatever field it comes, comments read as the shell reads them, quoted globs as text, substitutions in double quotes or backquotes as commands, here-document bodies read as data, a here-string as one word, interpreter code (python, node, ruby, perl) read for the deletes and moves it makes (`rmtree`, `removedirs`, `rmdir`, `shutil.move`, `os.rename`/`replace`, a `Path`/`Pathname` object's own, `FileUtils.rm_rf`/`rm_r`/`mv`/`remove_tree`, `fs.rm`/`rmSync` with `recursive`, `rmdirSync`, `renameSync`, Perl `rmtree`/`rename`) and the `rm -r` or `mv` its `os.system`, `subprocess`, `child_process` or backticks run, copies judged where they land (each source by the value it takes), links, case; a write whose glob or brace could reach a notes folder, and a recursive delete, move or rmdir (also a deleting `find`, or a recursive `chmod`, `chown` or `chgrp`) of anything holding one, up to the home folder and `/`; a path nowitknows cannot resolve, such as another command substitution or an unset variable, is refused only where something is written and only when its text names a notes folder specifically (brace lists and name-like globs included) and the part nowitknows can resolve is not elsewhere), allowing commands that only read: plain reads (`cat`, `head`, `tail`, `sed -n` printing, `grep`, `rg`, `ls`, `wc`, `stat`), builtins that only print (`echo`, `printf`, `true`, `false`, `:`), commands that only look (`test`, `[`, `[[`, `pwd`, `basename`, `dirname`, `realpath`, `diff`, `cut`, `tr`, `sort` without `-o` or `--output`, `find` without `-delete`, `-exec` or `-fprint`), `cd`, `pushd` and `popd`, joined by pipes, lists or loops, with no redirection but to `/dev/null`, no command substitution that does more than read, no in-place edits or program-running options, and no word or value that could give `sed`, `rg`, `sort` or `find` an option. The message of `git commit`, `git tag` and `gh` (`-m`, `--message`, `--title`, `--body`) is text when it holds no substitution. Beyond what that parsing resolves, a backstop refuses any shell command whose text, here-document bodies and here-strings included, names a notes folder or a path in one (links followed: literally, through `~`, `$HOME` or the command's variables, also ones its bodies set, relative from where a body runs, or by the text `.claude/projects/<x>/memory`) unless it only reads; this deliberately over-denies copying notes out (`cp -R <notes> /tmp/x`), reading them through an interpreter, and writing a file whose text names a notes path. This applies with the sandbox off and approvals never. Claude Code's own memory writes keep the existing gate; with its memory off, a Write, Edit or MultiEdit into the shared folder is refused in favor of the memory tool (a Bash command, `sed -i` or a redirect, is not read on Claude Code). These gates need enabled, trusted hooks, fail open on an error before they are built, and do not sandbox programs the model starts. Codex cuts a PreToolUse hook off after one second and lets the call through, so a call too large for the full check (over 60,000 characters), a check that runs past 0.4 s, or one that raises an error is judged by text alone: a notes folder spelled out in it, and not one plain read, is refused. They cover the forms a model naturally writes; deliberately obfuscated shell (`eval` of a built string, a base64-decoded command, an interpreter writing a path it computes), paths other programs build at run time, input typed into a running process, another MCP server's file-write tool (a path and content) and code in a field other than `cmd` or `command` are outside them. Whether real Codex honors the deny for `apply_patch` and `exec_command` is not yet checked live, and the shell parsing is POSIX (Windows paths and PowerShell are not read). A shell fed a script on its input has its own redirections judged like any other, and the gate follows only the folders of the newest recorded sessions plus the standard layout, so its work stays within the hook's limit on a machine with thousands of sessions.

Notes nowitknows kept before 0.8.0 are announced once for each repo and app and migrated only on request. Migration is add-only and preview-only by default; applying requires the quiet fence, and the preview names each repo's destination folder and the setting that chose it. Conflicts keep both notes, identical notes arrive once, overflow stays verbatim outside the notes folder with a notice, and the old copies stay in place beside migrated markers. Report the loss or overwrite of a Claude-written note or index line, a bypass of these write gates, or any access to Codex's native memory database as a security issue.
